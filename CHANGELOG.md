# Changelog

## Unreleased

BREAKING CHANGE: A per-call provider `url` -- `using(provider, model, {"url": ...})` -- that points at a loopback, private, link-local, CGNAT, metadata or otherwise non-public address is now refused with `private_address_refused` before the provider is built, so before any request. A url that is not absolute `http`/`https` is refused with `scheme_not_allowed`. Every IPv4 spelling a resolver accepts is checked (decimal, octal, hex, shortened such as `127.1`), as are bracketed IPv6 literals, IPv4-mapped/NAT64/6to4 addresses, `localhost` and `*.localhost`, and the cloud metadata names. The check makes no DNS lookup, so a hostname that resolves to a private address is not caught. It applies to built-in, named compatible and custom registered providers alike. CONFIG urls are unchanged: `OPENAI_URL` / `ANTHROPIC_URL` / `MISTRAL_URL`, the provider default and a `configure_providers` entry's `url` may still point anywhere, and a per-call url that is the same endpoint as the configured one is not checked. To allow private per-call urls, opt in in config, never per call: set `OPENAI_ALLOW_PRIVATE_PER_CALL_URL=true` (or `ANTHROPIC_`/`MISTRAL_`), add `"allow_private_per_call_url": True` to a `configure_providers` entry, or pass `register_provider(..., allow_private_per_call_url=True)`. A per-call `allow_private_per_call_url` key is ignored. Neither refusal names the url, host or address. New: `prism.public_url.is_public_address()` and `prism.per_call_url.assert_per_call_url()`.
- An ISATAP address behind a 6to4 prefix is judged by the IPv4 address it carries, in the guarded media fetch and the per-call url check alike; it used to be judged only by the 6to4 prefix. A per-call IPv6 literal with a trailing dot inside the brackets is refused.
- A per-call `url` host must be ASCII: an international name is given in its punycode (`xn--`) form, and any other non-ASCII host is refused with `non_ascii_host_use_punycode` before any request. Invisible and formatting characters, `ß`, `ẞ` and `ς` anywhere before the path are refused with `private_address_refused`. An IPv6 literal written with a dotted IPv4 tail is judged like its hex spelling.
- `configure_providers(entries, *, replace=False)` registers named OpenAI-compatible providers (`driver: "openai-compatible"`, `url`, optional `api_key`, `organization`, `project`, `api_format`). Each one uses only its own entry's credentials. It never reads `OPENAI_*` and never takes the `openai` provider's config. With no key it sends no `Authorization` header. A per-call url for a different endpoint drops the entry's credentials unless the call passes its own. Names, drivers, urls (absolute http/https only; a private address is allowed as the entry's config url), api formats and credentials are all checked before anything is registered. (G-321 A)
- OpenAI `api_format: "chat_completions"` is implemented for text, structured and stream, posting to `<url>/chat/completions`. Request bodies match the PHP reference byte for byte. A reply that finished on tool calls is refused with `tool_loop_not_supported` before any second request. Tool-call arguments that are not a JSON object are refused at mapping, and when read from a streamed call. A refusal from the model raises `provider_response_error`. (G-321 D)
- The default transports follow an HTTP redirect only while it stays on the request's own scheme, host and port, as in the PHP reference and prism-ts. A redirect anywhere else, to a Location that is not a valid http(s) url, or to one carrying a user name or password, is refused with `PrismError` (`redirect_refused`) before anything is sent to it, so request headers are never re-sent to another origin; more than 5 hops (the reference's limit: the sixth redirect) is refused with `too_many_redirects`. A same-origin 307 or 308 keeps the method and body; a 303, or a 301/302 answering a POST, becomes a GET without a body. This applies to built-in and named compatible providers alike. A transport passed to a compatible provider is still asked not to follow redirects.
- On chat completions, a user message carrying a document, audio or video part is refused with `unsupported_media`. The reference drops these parts without saying so.
- A stream that ends without a finish reason reports `unknown`, not `stop`.
- `ToolCall.to_dict()` no longer keeps the text of unusable arguments. Such a call is stored as `"arguments": "]"` with `"arguments_malformed": true`, as the PHP reference stores it, and `from_dict()` reads that record (or any record marked `arguments_malformed`) back as a call with unusable arguments. Records of usable calls are unchanged. This applies to every record holding a call: messages, steps and responses.
- Whether a tool call's arguments are usable no longer depends on how deep the caller's stack is. Valid arguments nested 500 levels deep were refused when the call was classified from a deep stack, because decoding and encoding them ran out of recursion room.

## 0.11.0 — 2026-11-23

BREAKING CHANGE: `ToolCall.decoded_arguments()` raises `malformed_tool_call_arguments` for a number, string, boolean, non-empty list or integer-keyed map. It used to return an empty dict for the first four. An empty string, the text `0`, `null`, `[]` and `{}` still mean no arguments. Code that reads the arguments before running a tool should catch the error and return it to the model as a tool error, or check `has_malformed_arguments()` first.
BREAKING CHANGE: Arguments the PHP reference cannot decode are refused too: `NaN` and `Infinity`, a lone surrogate, and more than 500 nested containers.
BREAKING CHANGE: A stored tool call with unusable arguments and no tool result now fails when it is sent. Answer it with a tool result first.
- `ToolCall.has_malformed_arguments()` says whether a call's arguments are unusable.
- Once a later tool result answers such a call, it is sent back with empty arguments in each provider's own shape (OpenAI, Anthropic, Mistral), including stored OpenAI output items. The caller's messages are not modified.
- A call that nothing has answered fails at mapping with `malformed_tool_call_arguments` on every provider, now including Mistral.
- Tests now check that core has no approval check and never runs a tool.

## 0.10.0 — 2026-11-23

BREAKING CHANGE: Credentials are now scoped to their configured endpoint; a per-call URL override must supply its own key. register_provider requires replace=True to replace a registered provider, and refuses any key that does not match ASCII `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, including a homoglyph or full-width look-alike, even with replace=True. A provider url, per call or from the environment, that contains whitespace or a control character anywhere is refused with ValueError before any request; it was previously trimmed for the endpoint comparison.

## 0.9.0 — 2026-11-05

BREAKING CHANGE: Distinguish omitted provider arguments from explicit `None` and empty strings. Nullable fields no longer fall back to environment when passed `None`; string-only null/scalar inputs are refused. See the README migration table.
- Honor `OPENAI_API_FORMAT`, canonical `ANTHROPIC_BETA`, and configured/environment default thinking budgets. Legacy beta fallback warns once without values and only if consumed. Integer per-request thinking budgets retain precedence.
- Forward only validated `timeout` and `connect_timeout` client options to every provider dispatch. Keep zero runtime dependencies and the standard-library urllib transport.
- Enforce nonstream total 30-second deadlines, including DNS and body reads. Streams have a 30-second header budget followed by Prism's 60-second body idle limit and no lifetime deadline. Preserve original-hostname TLS verification and pin validated guarded-media addresses through redirects.
- Preserve Mistral FIM rate-limit headers. Add native-backed provider configuration/FIM corpus cases and offline network-escape controls. Existing G43 offset and G125 native stream trace divergences remain open.

- Pin conformance to merged corpus 0.1.19 (`ae4b68bb923ac74030a5d88a924fdf1f09675caa`) with 162 native provider-configuration/FIM cases.
