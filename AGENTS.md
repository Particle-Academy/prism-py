## Zero runtime dependencies. This is a constraint, not a current state.

The package installs with nothing but Python 3.10+. No `requests`, no `httpx`,
no `pydantic`.

It is worth defending, because the pressure to break it always arrives as a
small convenience: a validation library for one schema, an HTTP client for one
retry helper. A library that sits underneath an application's own stack and
brings its own transitive tree is a library that causes version conflicts in
somebody else's resolver — and the cost lands on users who never asked for the
convenience.

Development extras (`pip install -e ".[dev]"`) are unconstrained. **Runtime is
not.** If something genuinely cannot be done without a dependency, that is an
ecosystem decision, recorded in prism-parity, not a line added to
`pyproject.toml`.

## A port, not a translation

PHP is the **reference implementation**: goldens are generated by executing it.
This package must produce the same bytes at the boundary while reading like
Python.

The tension has a decision:
[0002, idiom vs identity](https://github.com/Particle-Academy/prism-parity/blob/main/docs/decisions/0002-idiom-vs-identity.md).
**The wire is identical, the ergonomics are native.** Snake case, dataclasses,
exceptions where exceptions are Pythonic. A different request body is drift.

## Conformance

```sh
python -m pip install ./.parity/loaders/py    # the loader SHIPS the fixtures
python -m pytest -ra
```

The loader carries the corpus inside its own artifact rather than fetching it,
so this suite does not depend on prism-parity being reachable at test time.

When a case fails, do not edit the golden. Goldens come from executing the
reference; a disagreement means either this port is wrong or the reference moved
without the corpus being updated. Editing expected bytes to match this port
turns a caught bug into one enforced across every language.

## The Anthropic provider's five departures from the OpenAI shape

Each was found by a failing test rather than by reading documentation, and each
is easy to reintroduce while factoring the two providers toward shared helpers.

1. **`max_tokens` is required.** OpenAI defaults it; Anthropic rejects without it.
2. **The system prompt is a top-level field**, not a `system`-role message.
3. **Tool calls arrive as `tool_use` content blocks**, and `input` is already a
   **dict** — not a JSON string to parse, as OpenAI's `arguments` is.
4. **Tool results are keyed by the CALL id and sent in a `user` turn**, not a
   dedicated tool role.
5. **Cache tokens are reported separately and must NOT be subtracted** from the
   input count. Subtracting them under-reports usage — a bug that shows up on an
   invoice rather than in a suite.

## Gates

```sh
python -m pytest -ra
```

CI runs `tests`, `static` and `conformance`.

`agent/` is the MCP surface the Lab's team talks to. It listens on loopback and
belongs there: an agent that can run a suite and spend tokens is remote code
execution with a friendly name.

## When core changes

A change to request mapping, response parsing, error codes or value-object
serialisation in PHP core lands in the corpus in the same breath. This port
disagreeing with a freshly updated corpus is the system working. This port
disagreeing with a corpus that was *not* updated is a finding in core.
